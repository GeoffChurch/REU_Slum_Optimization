# Reporting & Examples Enrichment — Design

## Goal

Enrich the two flagship examples (`examples/method-comparison`, `examples/multiblock`) with the
metrics they currently omit — the efficiency curve, a hard-displacement view, and percentage
(area-normalized) reporting — and bring **CELF/lazy arterial** into both, so arterial rejoins the
multiblock (region) flagship it was previously dropped from for being too slow.

## Global constraints

- **No-legacy:** extend the existing emit/compare reporting; do not add parallel/deprecated paths.
  The existing `auc_table_*` / `tradeoff_table_*` CSVs and curve PNGs keep working unchanged; new
  columns are appended, not swapped.
- The compare harness and its four lenses (access, efficiency, directness, resistance) and two cost
  axes (`length`, `displacement`) are unchanged in behavior; this feature surfaces existing outputs
  and adds two derived columns.
- Examples are regenerated by re-running the documented `reblock.compare` reproduce commands; the
  READMEs are updated to match the regenerated artifacts (numbers must be current, not stale).
- Tests run with `pixi run pytest`.

## Feature 1 — Percentage (area-normalized) reporting  *(the code change)*

Two derived, area-normalized quantities computed from each method's **terminal** (full) road set on
a block, consistent with the corridor footprint the displacement metric already uses:

- **`pct_paved`** = `unary_union(roads).buffer(corridor_m).area / block_area` — the fraction of the
  block's area paved, using the SAME `roads.buffer(corridor_m)` footprint that `_displaced_points`
  (emit.py:60) buffers. `corridor_m = proposal.params.get("corridor_m", 3.0)` so it is defined for
  EVERY method (frontage methods like dijkstra/mesh don't set `corridor_m` in params → use the 3.0
  default; `pct_paved` measures total road footprint regardless of displacement, so it is a uniform
  "how much of the block is now road" quantity across all methods). `block_area` is already
  available in emit (`block_area_m2` column / UTM `geometry.area`, emit.py:147).
- **`pct_displaced`** = `len(displaced_points) / len(block.building_points)` — the fraction of
  buildings displaced (0 for frontage/length methods by construction).

**Where surfaced:**
- `pct_paved` → a new column in the length-cost `auc_table_{metric}.csv` (a road-cost quantity).
- `pct_displaced` → a new column in the displacement-cost `tradeoff_table_{metric}.csv` (already
  carries `mean_buildings_displaced`; add the normalized companion).
- Both are aggregated as the mean across the group's blocks (matching the tables' existing mean-AUC
  / mean-displaced aggregation).
- The example READMEs report **raw AND percentage** (e.g. "road density 260 m/ha (4.1% paved)",
  "543 displaced (12%)") — raw is not removed.

No new plot axis (the percentages live in the tables + prose).

## Feature 2 — Hard-displacement view in both examples

Run each flagship's compare a **second pass** with `cost=displacement` (the framework already swaps
the x-axis to "buildings displaced" and emits `tradeoff_table_{metric}.csv` + displacement-axis
curves, emit.py:240-271). Add those curves + the tradeoff table (now including `pct_displaced`) to
both READMEs.

Honest framing in the prose: displacement is the cost of **cutting through** buildings, so only
`arterial` and `clearance` (in displacement mode) register meaningful displacement; frontage methods
(`dijkstra`/`mesh`/`peel`) sit at ~0 displaced — which is exactly their advantage. The displacement
view is therefore primarily an arterial-vs-clearance tradeoff (navigability bought per building
moved).

## Feature 3 — Efficiency curve in multiblock

The compare already emits `curve_efficiency_{block}.png` (efficiency is one of the four lenses,
compare.py:125). The multiblock README simply omits it. Add the efficiency curve to the multiblock
README's method-comparison section, with the same "near-inert at scale — the many far-apart parcel
pairs swamp network E" caveat the method-comparison flagship already carries.

## Feature 4 — Lazy arterial in both examples

- **method-comparison** (single deep block 40972, all methods): switch the arterial entry to lazy —
  `GreedyArterialReblocker(lazy=True, candidate_policy="grow", ...)`. One arterial row (replaces the
  exact entry). In `conf/compare_config.yaml`'s `all_methods.greedy_arterial_buildable` set
  `lazy: true, candidate_policy: grow`.
- **multiblock** (region flagship, block 5810): add lazy arterial to the scalable-methods list
  (`methods=[dijkstra,peel,mesh,clearance,greedy_arterial_buildable]`), so **arterial rejoins** the
  comparison it was dropped from. This is the headline payoff of the CELF work.

**Tractability check (regeneration-time, in the plan — not a code risk):** block 5810 has 6,619
parcels vs the CELF smoke block's 263. Lazy cuts the per-step cost, but the one initial full pass
still scores all candidates once (pooled over `workers`). The plan MUST measure lazy arterial's
wall-time on 5810 during regeneration; if it is impractical (say > ~10 min), reduce `n_anchors`
(quadratically fewer candidates) and record the chosen value + timing in the README's reproduce
block. Document the actual command + runtime so the example stays reproducible.

## Testing

- **Unit tests (emit)** for `pct_paved` and `pct_displaced`: a known road set on a known/synthetic
  block yields the expected fraction (paved-area / block-area; displaced / total), plus the
  empty-roads edge case (`pct_paved == 0.0`, `pct_displaced == 0.0`, no crash).
- Existing emit/compare tests keep passing (the new columns are additive).
- Example regeneration is validated by the compare running clean and the READMEs matching the
  regenerated artifacts (docs/artifacts, not unit-tested).

## Non-goals

- No change to the four lenses, the two cost axes, or the cost-benefit math.
- No new plot type or axis for percentages (tables + prose only).
- No exact-vs-lazy arterial comparison rows (lazy replaces exact in the examples).
- Not re-deriving displacement for frontage methods (they displace 0 by design).
